# ACTION MODEL SPEC 001 — 「やりたい」を実行可能な次の一歩へ変換する

対象：LIFE DESIGN LAB やりたいことルーレット
状態：仕様案。公開ベータへの適用前。

## 目的

現行カードには「今日できる行動」「準備が必要な体験」「中長期目標」「継続習慣」「関係性・価値観」が混在する。ルーレットはカード自体を完了させる装置ではなく、**選ばれた“やりたいこと”に今日から近づくための入口**として扱う。

## 5つの action_type

| code | 名称 | 定義 | 抽選後の基本CTA |
|---|---|---|---|
| NOW | すぐ実行 | 今日〜数日で単独実行しやすい | 「今日やる」 |
| PREP | 準備型 | 予約・場所・道具・同行者など準備が必要 | 「最初の準備を決める」 |
| GOAL | 中長期目標 | 数週間〜数年の計画・資源が必要 | 「最初の一歩を決める」 |
| HABIT | 継続習慣 | 繰り返して成立する行動・状態 | 「最初の1回を決める」 |
| REL | 関係性・価値観 | 相手や関係性、望む状態を含み単純な完了判定が不向き | 「できる働きかけを考える」 |

## time_horizon

`today` / `days` / `weeks` / `months` / `years` / `ongoing`

action_typeと時間軸は別属性にする。例：「毎朝散歩」はHABIT + ongoing、「海外で1か月暮らす」はGOAL + months/years。

## 初回分類ルール

1. 1回の行動として実施可能ならNOW。
2. 実施前に予約・移動・準備が主に必要ならPREP。
3. 成果状態の実現に複数工程が必要ならGOAL。
4. 「定期的」「習慣」「続ける」「日常的」等を本質とするならHABIT。
5. 他者との関係の質・相互作用が成果ならREL。
6. 複数に当てはまる場合は、カード本文が最終的に求める状態を優先する。

## UI仕様

### 抽選前
「今日、何しよう？」を将来的に「次に、何をやってみる？」へ変更候補とする。NOWだけを抽選する「今日できる」フィルタも検討。

### 抽選結果
1. やりたいこと本文
2. 種別バッジ（例：中長期目標）
3. 「まずはここから」欄
4. CTA
5. 「やってみた！」の代わりに、type別の進捗操作

### 完了操作
- NOW / PREP: 「やってみた」
- GOAL: 「一歩進めた」
- HABIT: 「今日できた」
- REL: 「働きかけた」

カード自体の恒久的な完了と、今回の一歩の実行を分離する必要がある。現行の `done[]` は「カード完了」扱いのため、正式実装ではイベント履歴への移行を検討する。

## データモデル案

既存IDと回答を壊さないため、カード本文とは別にメタデータを追加する。

```json
{
  "id": "W001",
  "actionType": "GOAL",
  "timeHorizon": "months",
  "firstStep": "候補地を3つ書き出す"
}
```

利用履歴は将来的に：

```json
{
  "cardId": "W001",
  "action": "step_completed",
  "at": "ISO-8601"
}
```

とし、`answers`（興味判定）と`progressEvents`（実行履歴）を分離する。

## 実装順

1. 全200件にaction_type / time_horizonを付与する。
2. firstStepをまず高優先カードから作成し、品質基準を確定。
3. 既存localStorage v1から壊さず移行できるstate v2を設計。
4. 抽選結果UIを変更。
5. NOWのみ／すべて等の抽選フィルタを追加。
6. 自動テストに各typeの抽選・保存・移行を追加。
7. 公開ベータで検証後に正式版へ。

## 非目標

- 現段階で200件の本文やW001–W200 IDを変更しない。
- REL型を「完了／未完了」の単純な達成評価にしない。
- 健康・金融などのカードについて、個別の専門助言を自動生成しない。
