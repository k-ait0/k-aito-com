Web制作ツールを探していたら、結局「HTML/CSSを原本にする」に戻ってきた

直感操作できるツールを探していたはずが、最後は「何を原本として残したいか」という話になった。

AIにHTMLやCSSを書いてもらえば、Webサイトの初期制作はかなり速い。ただ、その後の細かなUI調整になると少し面倒だった。

微調整を毎回AIに説明するのが面倒だった

「ここの余白を少し狭く」「カードをもう少し右に」「スマホでは1列に」。こうした変更を毎回文章で説明して、結果を見て、また説明する。できなくはないけれど、自分で画面を直接触った方が速い場面が多い。

自分で画面を直接触れた方が早いのでは？

最初はFramerがかなり良さそうだった

最初に気になったのはFramer。見たまま要素を動かし、余白や配置、文字サイズを調整できる感覚はかなり分かりやすい。LPや一般的なWebサイトなら、これで十分快適になりそうだった。

でも、今後作りたいのは本当に「Webサイトだけ」なのか？

でも、作りたいものはもっと広かった

記事サイトだけではなく、シミュレーター、診断ツール、データベース、家系図エディター、管理画面のようなものも作りたい。そこでWeWebやBubbleのような、Webアプリまでまとめて扱える環境が気になり始めた。

一度は、「1つのツールに集約した方が楽なのでは？」という方向に考えが進んだ。

「1ツール」と「簡単」は同じではない

統合型ツールはできることが多い。その一方で、データベース、ワークフロー、API、認証、条件分岐、状態管理など、そのツールの中で理解することも増える。

「1つのツールを使う」ことと「1つのツールだけ覚えれば済む」ことは違う。

自分が求めているのは、全部入りそのものより、普段触る操作方法を統一することなのかもしれない。

決定打は「コードを原本にしたい」だった

さらに考えていくと、もう一つ条件が出てきた。

HTML / CSS / JavaScriptを、最終的な原本として残したい。

GUIで調整しても変更は普通のコードとして残る。逆にAIがコードを直接変更しても、GUI側で同じ結果を確認できる。この往復が理想だった。

つまり欲しかったのは、GUIからコードを書き出すツールではなく、GUIでもコードでも同じ成果物を直接編集できる環境だった。

欲しかったのは、コードを視覚編集する環境だった

ここまで条件を整理すると、一般的なビジュアルビルダーとは少し違うものを探していたことが分かった。そこでPinegrowがかなり有力になった。

HTML/CSS/JSを中心に置きながら、自分はビジュアル側から触り、AIはコード側から触る。両者が別々の成果物を持たなくていい。

ツールだけでなく、運用もセットで決める

最終的には、ツール単体ではなく制作フロー全体をセットで決めることにした。

Pinegrow自分が画面を見ながら直感操作する場所。
HTML / CSS / JavaScript唯一の原本として残す。
GitHub変更履歴とバックアップを管理する。
ChatGPT / Codex複雑な実装やコード修正を担当する。
  1. コードを唯一の原本にする。
    GUIはコードを扱うための操作面として考える。
  2. PinegrowとAIが同じファイルを同時編集しない。
    片方の変更を確定・反映してから、もう片方が作業する。

これなら、自分は画面を触れる。AIはコードを触れる。そして、最終的に残る資産は同じになる。

まとめ

今回、Framer、統合型のWeb制作環境、Pinegrowと候補が変わった。一見すると迷走しているようにも見える。でも比較するたびに、自分が求めている条件が一段ずつ具体化していった。

先に決めるべきだったのは、「最高のツールは何か」ではなく「何を原本として残したいか」だった。

だから現在の答えは、「Pinegrowが最高だから使う」ではない。

HTML/CSS/JSを原本にする運用に、一番合わせやすかったから使う。

これは2026年9月時点の制作環境を決めるための記録。実際に運用して問題が出れば、その経緯もまた残していく。
