# KIDP Wave A Recruitment & Session Kit — 2026-10-08

Status: READY TO RECRUIT
Scope: KIDP-004 駅生活圏 / KIDP-003 LIFE DESIGN LAB

## Objective

Wave AではPrototypeを増やさず、
KIDP-004とKIDP-003を各5人で初回Decisionまで閉じる。

推奨:
- 10 unique participants total
- 5 for KIDP-004
- 5 for KIDP-003

調達が難しい場合:
- 最大2人まで両案件へ参加可
- 同日に連続実施しない
- 24時間以上あける
- 2案件間の比較データとしては扱わない

## Incentive

初回P0は15〜20分を目安。
謝礼を付ける場合の内部目安:
- 500〜1,000円相当 / session
- 友人・知人の協力の場合は無償でも可
- 謝礼の有無で評価を甘くしないよう「良い点より分かりにくい点を知りたい」と明示する

## Pool A — KIDP-004 駅生活圏

Need 5.

Target mix:
- 2人: 通勤型
- 2人: Hybrid / 在宅型
- 1人: 夜型 / 休日行動が活発

Across the five:
- 3人以上: 賃貸・引越し経験あり
- 1人以上: 最近3年以内に部屋探し経験
- 1人以上: 「駅徒歩」をかなり重視する人
- 1人以上: 駅距離以外を重視する人

Avoid:
- 不動産実務者だけで固める
- KIDP-004の設計意図を事前に知っている人だけで固める

## Pool B — KIDP-003 LIFE DESIGN LAB

Need 5.

Target mix:
- 2人: 目標が比較的明確
- 2人: やりたいことが曖昧
- 1人: 自己分析ツールにあまり関心がない

Across the five:
- 1人以上: 自己分析ツール好き
- 1人以上: 自己分析ツールを普段使わない
- 1人以上: キャリア以外のテーマに関心が強い

Avoid:
- 全員が自己分析好き
- 全員が同じ年代・職種・生活状況

## Recruitment channels — priority order

1. 直接依頼できる友人・知人
2. 以前の同僚・学校関係者
3. SNSの軽い募集
4. 必要なら有償モニターサービス

初回5人は統計的代表性より
「異なる反応が出る最小構成」を優先する。

## Session length

### KIDP-004 — 15 minutes

0:00–1:00
- greeting
- 「試作品側のテスト」と説明
- prototype URLを開く

1:00–8:00
- free exploration
- facilitatorは助けすぎない
- 詰まった場合のみ「思ったまま触ってください」

8:00–13:00
- fixed post-test questions
- participant answers M1–M4 related questions

13:00–15:00
- missing information
- first quote / final comments
- CSV copy
- Test Ops DONE / INVALID

### KIDP-003 — 18 minutes

0:00–1:00
- greeting
- fixed start script

1:00–10:00
- 20-card Swipe
- do not explain category logic
- note cards taking 5s+

10:00–15:00
- Interest Map reaction
- deep-dive choice
- diagnostic-misread question

15:00–18:00
- missing card / confusing point
- CSV copy
- Test Ops DONE / INVALID

## Facilitator opening

「今日はあなたをテストするのではなく、試作品の方をテストします。
正解はありません。
分かりにくいところがあれば、そのまま分かりにくいと言ってください。
こちらから説明しすぎないようにするので、まず自由に触ってください。」

## Neutral prompts

Allowed:
- 「今、何を考えていますか？」
- 「そう思った理由を教えてください」
- 「次に何をしたいですか？」
- 「この表示をどういう意味だと思いましたか？」
- 「分からない場合は分からないで大丈夫です」

Avoid:
- 「この点数はこういう意味です」
- 「おすすめが変わるの分かりますよね？」
- 「結果、自分っぽいですよね？」
- 「SAMEはLikeではありません」のような正解誘導

## Invalid session

Mark INVALID if:
- prototype fails to load and meaningful interaction cannot continue
- participant already knows the target hypothesis in detail
- facilitator accidentally explains a key metric before the participant interprets it
- participant is interrupted for a large part of the session
- another person operates instead of the participant
- test data is obviously from QA/sample mode

Do NOT mark invalid merely because:
- participant dislikes the prototype
- participant misunderstands the score
- participant stops early due to low interest

Those can be valid negative signals.

## After each session

1. Complete tester observation fields.
2. Copy participant CSV row.
3. Save into local working log.
4. Mark DONE or INVALID in Test Ops.
5. Do not redesign yet.
6. After 5 valid sessions, paste rows into Review Tool.
7. Save Decision before discussing new features.

## Stop rule during recruitment

Do not stop after 1–2 bad reactions.
Complete 5 valid participants unless:
- prototype is technically unusable for all participants
- a severe privacy/safety issue is discovered
