# K. Aito Analytics｜旧Shillerスナップショット復元監査 v0.19

**2026-11-13 JST｜RESEARCH_ONLY_HOLD｜公開・商用配信・権利利用未承認**

## 実際の調査結果

- `analytics-historical-v0-1-20261110` の正本は、1980-01～2023-06の522か月を旧版Shiller研究系列として固定している。保存済み原本のバイトSHA-256：`0cdb8a04bd14d104e53acbb982cf205eb4733371bb9140191b8c4b6e433bc55d`。
- 原典として登録された `datasets/s-and-p-500` の `data/data.csv` をGitHubコネクターから取得し、2026-11-01コミット `87a2284276f79d75041c71c8f6d9f2aa1c965e84`、Git blob SHA-1 `1c5f64a1cb8377fde80d339fbf0051e5e0e94566` を確認した。
- 同ファイルの1980-01～2023-06は522か月。列は `Date, SP500, Dividend, Consumer Price Index` 等。2023-07以降はFREDの価格のみの延長で、配当/CPI等の0を旧Shiller観測と誤認してはいけない。
- 固定4列への変換について、**価格・配当・CPIの数値表記を各9通り×改行2通り×末尾改行2通り＝計2916通り**試したところ、上記の旧版原本SHA-256と一致する候補は**0件**。見つかった公開元CSVのそのままの利用は既存正本への受入不可。
- 旧ソースと公開元のバージョン差異・端数処理・復元時の独自ルールが原因となる可能性はあるが、**原因を確定したわけではない**。不一致を解消するために固定SHAや取得元ロックを勝手に変更しない。
- 再配布元はODC-PDDLを表示している一方、Shiller原データのライセンスは断定していない。従ってサイト公開・商用再配布の権利を確認できたという意味ではない。

## 新しい実装

`lib/analytics/private-shiller-recovery.cjs` と `scripts/recover-analytics-private-shiller-v19.cjs`。

1. 選択肢A：ローカル保管先の `.csv` を再帰走査（リンクは追わない）し、**原本バイトSHA-256が完全一致するファイルだけ**を報告。CSV本文は表示・送信しない。
2. 選択肢B：公開元の上記コミット**1件だけ**を明示オプションで取得。リダイレクト・別ホスト・取得超過・Git blob改変を拒否する。取得はユーザー所有PCに限定し、GitHub等への再アップロードはしない。
3. 原本再構成の候補探索は検証のみ。固定SHA-256に一致した場合に限り、Gitチェックアウト外に0600で `raw-shiller.csv` を新規作成する。一致しなければ終了コード2で停止し、出力ファイルを作らない。
4. 入力は**522か月**を必須とし、期間、連続性、10列ヘッダー、数値有効性を検証。2023年7月以降の価格のみの延長は採用しない。
5. ソース正本・ADR・Coreの正本ハッシュは変更しない。新たなSHILLER研究チャネルへの切替も行わない。

## Windowsでの次の一手

v0.19研究ブランチのチェックアウト（Node.js 22）でPowerShellを開く。

```powershell
# 最優先：過去の旧Shiller原本を、手元で持っているフォルダーから探す。ネットワークなし。
node scripts/recover-analytics-private-shiller-v19.cjs `
  --search-dir 'C:\AnalyticsPrivate'

# 見つからなかった場合：固定コミットの公開元から「候補の比較だけ」を行う。明示的な単発通信。
node scripts/recover-analytics-private-shiller-v19.cjs `
  --fetch-once --inspect-only
```

- 一致した場合：ローカルパスが表示されるので、そのファイルをv0.12 `--shiller` の引数に指定する。
- 一致しない場合：旧原本を捏造したり、公開元の現行データで代替したりしない。データ取得担当による元の正本スナップショットの再確認、または**独立した新しい研究版としてのソース変更ADR**が必要。
- `--source-file` は公開元から別途合法的に得た上流CSVの検証用。旧4列CSVの検出は `--search-dir` によるバイトSHA照合を使う。
- `--fetch-once --out-dir 'C:\AnalyticsPrivate\ShillerRecovered'` は、**もし固定SHAと完全一致する復元候補が存在した場合だけ**そこに保存する。現在の検証結果からは不一致が予想される。
- 以上の経路ではRSA秘密鍵を読む必要がなく、暗号化Artifact 5件を復号するわけでもない。
