# A05 D-53 — データ上書きを伴わない復元前リスク検査／公開境界の自動確認

**2026-10-26｜D53-001｜研究未承認・Draft PR #61・本番非公開**

## 1. 実施結果の要約

D-52で「バックアップJSONの形式・件数を確認できる」ところまで進んだ。しかし、この確認結果だけでバックアップを復元可能だと判断すると、現行の端末に保存済みの診断や保存同意の扱いを誤りかねない。

D-53では、**復元機能自体は実装せず、復元前の潜在的な問題を検出する読み取り専用の事前検査**を追加した。主な改善点は次のとおり。

- A05の全5ストア（下書き、履歴、設定、移行、旧版バックアップ）の**保存件数だけ**を、1つのreadonly IndexedDBトランザクションで取得する。回答内容・IDを端末DBから一括読出ししない。
- 選択したローカルJSONの履歴レコードを、現行バージョン基準で「**検証済み形式／旧版／隔離対象**」に数値分類する（現行の `classifySnapshot` を再利用）。下書きは現行版の`verifyDraft`に照合。
- **既存端末に1件でも保存データがあれば上書き禁止**と判定。これは「いずれ空になれば復元できる」と約束することではない。
- バックアップ内の「保存に同意済み」の情報を新端末の同意に引き継がない。原本の真正性・所有者・暗号学的完全性も未確認と明示。
- 返すのは件数と固定された一般的な問題コードのみ。取り込んだ回答・氏名・個別ID・文面・秘密を画面、ログ、アプリ状態に残さない。
- **`restoreAuthorized:false` / `restoreImplemented:false` / `anyDataWritten:false` を常に固定**。空端末かつ現行版のバックアップでも、復元は行わない。

**重要な時間差の制約**：件数取得のreadonlyトランザクションは、未来の復元トランザクションと原子的につながっていない。別タブによる更新が後から発生し得るため、将来インポータを実装する場合は、実際の書込み時に競合と同意を**改めて原子的に再検証**する必要がある。D-53の結果を復元許可として利用してはいけない。

**構造検査・現在版照合は真正性の証明ではない。** 加工されたJSONが見かけ上正しいことはあり得る。データの出所、所有権、適用規程、取り込み安全性は依然として人による判断が必要である。
