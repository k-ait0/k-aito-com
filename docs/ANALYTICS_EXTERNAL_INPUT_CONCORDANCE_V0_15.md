# K. Aito Analytics｜v0.15 外部入力―月次資産台帳の照合監査

**2026-11-12 JST｜RESEARCH_ONLY_HOLD／一般公開・投資判断・商用再配信は未承認**

## 目的と監査で発見した不足

v0.14 の `portfolio-ledger-audit.cjs` は、**台帳内の数値同士の整合性**（資産別残高・資金流出入・騰落率・月末残高）を検査する。しかし、もしシミュレーションへ渡す元の市場リターンや積立金額を別の値に置き換えてから、数学的に一貫した台帳を作った場合、台帳内部の監査だけではその置き換えを見抜けない。

v0.15 は、**元入力を別引数で保持したまま、台帳の全月・全資産を独立計算で照合する追加監査**を実装した。従来の監査はそのまま存続する。

## 新規実装

- `lib/analytics/portfolio-input-audit.cjs` — `auditPortfolioAgainstInputs(originalInputs, portfolioSimulation)`。入力条件の検証後、内部台帳監査に加え、外部入力の通貨・月次額・元リターン・初期残高・資産識別子・目標ウェイト・定期／閾値リバランス・端数配分・ターンオーバー・最終残高を**全月分**突合する。
- `lib/analytics/rolling-portfolio-lifecycle.cjs` — 全ての完走ローリング開始月について監査を必ず通す。`input_concordance_audited_windows` を結果に記録。
- `lib/analytics/rolling-portfolio-cpi.cjs` — 日本CPIによる生活費調整後、各開始月のシミュレーションに対応する入力と台帳を照合。CPI欠損月を跨ぐ除外窓は「監査完了」と数えない。
- `scripts/test-analytics-portfolio-input-audit.cjs`、`scripts/test-analytics-portfolio-input-rolling.cjs` — 元市場リターンや入出金を改変したものの、内部台帳監査ではPASSするケースを**外部入力監査でFAILさせる**攻撃的テスト。通常ケース、日次ではなく月次の複数資産、閾値・定期リバランス、月別支払、端数、初期資産ゼロも検証。

入力監査は再計算の条件一致を保証するが、**入力値それ自体が実測値であることは認定しない**。大部分の月次端数配分・投資利得ロジックは JavaScript `Number` による仕様に合わせており、基準となる独立した高精度金融アクチュアリー・エンジンによる実市場Golden照合も未実施。

## 計算境界

- 統合計算では名目円建てリターンと名目キャッシュフローを前提とする。リバランスは手数料・税金なし、月末に実行。
- 出資 → 資産比率による払戻 → 資産別リターン → 指定方針リバランス、の順序を照合。
- 監査は最大12資産×1200月の入力を受け、月次ごとに独立再計算する。ローリングごとに監査した窓の数は表示する。
- イベント・年金・CPI連動の時系列解釈はv0.13およびv0.14の仕様を維持し、CPI欠損を補完・代理・推定しない。
- 観測月が重なるローリング開始期間は互いに独立な試行ではなく、将来の成功確率とも呼ばない。
