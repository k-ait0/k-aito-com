## 3. 実行手順（GitHub Actionsなし）

同ブランチに\`scripts/qa-a05-phase1-virtual-browser-20261104.py\`を新設。ローカル環境へ**実原本を配置した場合**に実行できる。直接file://が禁止されている環境ではPlaywrightの\`page.set_content\`で実HTMLを描画する。

\`\`\`bash
node --test scripts/test-a05-phase1-short-reports-20261104.mjs
python3 scripts/qa-a05-phase1-virtual-browser-20261104.py \
  --out .a05-qa/phase1-virtual-20261104
\`\`\`

ブラウザランナーでは2種類の完全網羅（16自己タイプ＋16×16順序付きペア）をデスクトップ／スマホ各一巡し、320pxと768pxで代表パターンを実行する。JSONレポートと4枚の代表スクリーンショットを出す。\`file://\`と同じorigin挙動、実タッチの感触、iOSのテキスト拡大・VoiceOverは**未検証**と明示する。

**制約に遭遇したら**：①直接実行可否 ②仮想・モック代替 ③問題を切り離した先行作業、の順に試す。どうしても必要な手操作のみ最終実機工程に残す。ブラウザを使えない場合でもQ1/Q5/Q6を止めない。

## 3.1 A05診断本体・統合後のQA（別トラック）

この計画は簡略版152件だけで終わらせない。A05本体PR #61も仮想QA対象とし、**診断の機能QA**と**文章の内容・研究判断**を分離する。

| トラック | 仮想環境・モックで検証する事項 | 開始条件 |
|---|---|---|
| D1 回答フロー | 30問×7段階、途中保存なしの利用、回答不能、戻る/修正、30問完了・不足回答時の状態 | PR #61の本体ファイルを実行環境に固定できた時点 |
| D2 暫定計算 | 4軸タイプと第5軸Eの既存暫定分離、境界・欠測・保留、16タイプ全件の分岐、旧Q/S/T/Cの不変 | 既存Nodeユニットテスト＋模擬入力 |
| D3 端末保存 | Chromiumの仮想IndexedDBで同意前の無保存、同意後の履歴保存・読込、削除・raw回答保持設定、バックアップ/復元、壊れた履歴の隔離 | フェーズ1の単独プレビューとは独立して実施 |
| D4 セキュリティ | 回答・履歴・共有文面から外部送信なし、XSS、安全な表示エスケープ、バージョン不一致時の扱い | 監査対象と保存契約を固定 |
| D5 正式統合 | 診断結果のタイプと簡略版レポートの対応、判定保留時の非表示、R1比較への遷移、将来のモデル版変更に伴う誤分類防止 | **S1分類の決裁／編集受入後のみ**、現行本体の強制結合は禁止 |

D1〜D4は、分類の科学的有効性を主張せずに**現行実装が仕様通り動くか**を先に検証できる。D5はS1の承認状況に依存するため、統合先の仕様が決まるまでテストケース設計とモックまで進め、未承認の本体ソースへの接続を行わない。

診断本体と簡略版で同一「QA合格」ラベルを使わず、\`CONTENT_QA\`、\`DIAGNOSTIC_FUNCTION_QA\`、\`INTEGRATION_QA\`、\`EDITORIAL_APPROVAL\`、\`PSYCHOMETRIC_RESEARCH\`、\`FINAL_DEVICE_QA\`の六つに分けて記録する。

## 4. チェック項目の優先順位

- **P0 公開阻止**：違うタイプ・組合せの表示、データ欠落、危険な断定・保存・送信、JS例外で閲覧不能、編集未承認の公開導線。
- **P1 公開阻止**：320pxの重大な操作不能、見出し/選択操作がキーボードで不能、重要な説明の切れ・表示欠落、原稿更新がプレビューに反映されない。
- **P2 改善対象**：余白・装飾の微調整、文体の揺れ、軽微な表示差。修正可否と判断をQA台帳へ記録。

自動テストのPASSと、ユーザーによる文面の正式採用、科学的評価は**別のステータス**で管理。未承認稿はDraftに維持。

## 5. 実機QA（最終段階）まで保留するもの

iOS Safari（ファイル読込/本番URL双方）、iPhoneでの表示と実際のタップ感、OSの文字拡大、VoiceOver読み上げ、実端末での印刷・共有、公開サイトの環境固有動作。これらは**最終公開の品質ゲート**とし、合格前に本番へ反映しない。
