## 2. D230で新たに実装した内容

1. **元30問セットの完全照合**：`drawResearchHoldFilteredManifest(seed)`を再実行し、seedと設問ID、軸、表示順、設問文、出典を含む元manifest全体を順序込みで照合。
2. **元の回答スナップショットを固定**：30問分の質問IDに対する1〜7または明示的な`null`をすべて必須にする。欠落・余分な項目・型不正を拒否し、SHA-256ダイジェストを記録。
3. **追加質問の決定再生**：前段階の回答からD227の追加質問選定を毎回再計算。なぜその軸に2問追加したか、どの順番の2問だったか、30→32→34のセット全体が一致するか検証。
4. **履歴の連鎖照合**：前段階ハッシュ、回答の差分、選定理由、次のmanifestをまとめたハッシュ連鎖で、不整合と事後的な部分改変を検知。2回の上限を超えた履歴を拒否。
5. **独立した参考計算**：既存`scoreResponse`や`scoreResearchForm`を呼ばない参照計算を別に作り、軸別平均値、符号、設問/意味グループ除外時の反転、判定状態、16タイプ候補集合を照合。
6. **不正入力テスト**：異なるseed、設問順や設問文の変更、回答改変、履歴上の別軸への付け替え、追加質問ID・順番の改変、前段ハッシュ破損など52,400例を拒否。

## 4. 依然として存在する制約と未解決問題

### (a) SHA-256ハッシュは独立の認証ではない

D230は**内部の整合性検証**であり、第三者が記録全体を作り直し、すべてのハッシュを再計算すれば、元記録との区別はできない。

本人確認、回答者の真正性、外部からの改ざん防止を実現するには、信頼された外部ログ、署名、鍵管理、あるいは別の固定アンカーが必要。このゲートはその仕組みを実装したという意味ではない。

### (b) 1.5乗は心理測定上の最適値ではない

1.5乗を選んだ根拠は人工データ上の外れ値耐性と設計意図の折衷である。実際の回答傾向・回答スタイルによっては、線形方式より悪い可能性もある。

### (c) 33.3%に相当する境界閾値は未較正

`(1/3)^1.5`を暫定の弱い選好の境界として採用する数学的説明は可能だが、信頼度や再検査一致率に対して適切かは実回答で検証する必要がある。D230テストはこの閾値の**実装整合性だけ**を見ている。

### (d) 質問の内容と二極尺度の限界

C36の差し替え候補は未確定、18組の類似設問に本人の回答理由による評価がなく、B/Cで「両方を大切にする」「両方を重視しない」を4から区別できない。これは**第2段階を通過するための主要な未解決問題**である。

### (e) 追加質問の選択は情報利得最大化ではない

新しいD230は正しい選定履歴を再生できるが、選定が人間にとって最適であるという実証ではない。30問と34問の比較には、実回答の選択バイアスと見かけの安定性を分ける検証が必要。
