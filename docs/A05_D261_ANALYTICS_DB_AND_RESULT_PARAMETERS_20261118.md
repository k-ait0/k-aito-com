# A05 D261｜設問品質DB・16タイプ分布・結果画面指標の設計（2026-11-18）

**状態：ARCHITECTURE_PROPOSAL_FOR_REVIEW／NOT_DEPLOYED／NO_DATA_COLLECTION.**
この資料はVer.2.1を読み取り、次版の技術設計を先に固めるもの。現在公開中のVer.1／Ver.2／Ver.2.1／D242のコード・配信HTMLを変更しない。実際の回答者データは未取得。

## 0. 決定の解釈

1. **将来**、設問ごとの「判断できない」（UNKNOWN）が一定割合を超えた際には、設問文・回答の選択肢・意味領域・非該当率をレビューし、別の設問への入れ替え候補にできる設計にする。ただし**自動入れ替え機能は今は実装しない**。
2. その前提として、回答選択率・設問別UNKNOWN/NOT_APPLICABLE率・中間4の割合・Y/NのYES/NO/UNSURE率・16タイプの出現割合などを**バージョン付きで集計可能なDBモデル**を定義する。
3. 16タイプを無理に1つへ配分しない。未確定、30問での単独タイプ、Y/N補完での単独暫定タイプを区別し、アルゴリズム更新前後で混在させない。
4. 診断結果画面の4軸パラメーターも再設計する。新しい評価式・基準値の変更は別ゲートとし、D255の採点へ黙って組み込まない。

## 1. 現行実装を確認して判明した注意点

- `scoreAnswer(x)=sign((x-4)/3)*abs((x-4)/3)^1.5`。30問の各軸で`ratio = sum(scoreAnswer(x))/validCount`、結果バーは`50+50*ratio`を幅として利用している。
- 中間`4`は**有効な回答**（分子0、分母1）。`UNKNOWN`と`NOT_APPLICABLE`は`answers[id]=null`で、`skipReasons[id]`に別理由を保持し、分母から除外する。
- バーの幅はあくまで研究用の**軸得点位置**で、確率・信頼区間・精度・「その価値観を持つ人の割合」ではない。
- `status=clear`以外には`few_directional / insufficient / tie / borderline / fragile`がある。左右の相殺、4の連続、無回答は別の事象であり、同一視しない。
- D255は`BASE_30`に優先権を与え、未確定軸のみY/N2問等で別層として暫定補完する。**7段階のスコアは再計算しない**。このためY/N補完タイプの軸位置をそのまま「確率xx%」と表示してはいけない。
- 現行プレビューは`CSP connect-src 'none'`／回答の外部送信なし／タブを閉じると消失。**今DBは存在せず、データ収集もしていない**。後付けで過去の回答を復元できない。

## 2. 設問品質モニタリング：保存すべき事実

| 種別 | 値 | 用途 |
|---|---|---|
| 設問定義 | question_id、question_revision、本文digest、axis、response_format、semantic_family | 設問の文章を改訂したら版を分ける |
| 出題版 | questionnaire_version、manifest_variant、ordinal、scoring_version、classification_version | 128フォームの不均等な露出・新旧版の混同防止 |
| 回答 | CORE: 1..7/UNKNOWN/NOT_APPLICABLE、YN: YES/NO/UNSURE/NOT_ANSWERED | 回答理由・形式ごとの正しい集計 |
| 出題（exposure） | その設問が回答者に提示された回数 | 「全受検者数」を誤って分母にしない |
| 診断の結果 | BASE_30とFINALの各status、単独タイプIDまたは未確定、候補数、Y/N補完軸数 | 16タイプの出現割合・Y/Nの寄与 |
| 軸の解析結果 | A〜D各sign、evidence_source、score_ratio、valid_count、directional_count、midpoint_count、UNKNOWN_count、NOT_APPLICABLE_count、fragile等 | グラフ再設計・監査 |
| 版と期間 | 日付（JST）、bank/scoring/classifier/formバージョン、質問改訂番号 | 時系列比較と異なる規則の分離 |

**識別子の原則**：`question_id`は変わらない論点を示すが、設問文・選択肢・スケール意味を実質変更したら`question_revision`を上げる。別の意味内容へ差し替えるなら新しいquestion_idとし、旧版を上書きしない。

### 分母と割合の定義

```text
設問別「判断できない率」 = UNKNOWN回数 / 同じ設問版を提示した完了セッション数
設問別「当てはまらない率」= NOT_APPLICABLE回数 / 同じ設問版を提示した完了セッション数
7段階の中間4率         = 4回数 / その設問版で1..7を回答した数
7段階の各選択肢割合    = 選択肢k回数 / その設問版で1..7を回答した数
Y/NのUNSURE率          = UNSURE回数 / そのY/N設問版で実際に回答した数
総合非方向回答率       = (4+UNKNOWN+NOT_APPLICABLE) / COREの提示回数
```

未回答のままY/Nを途中終了した場合は`NOT_ANSWERED`として別扱いし、`UNSURE`に混ぜない。開始のみで30問を完了しなかったセッションは初期の集計対象外にする。したがって初期値は**完了者条件付きの率**であり、全訪問者・一般人口の率ではない。

### 将来の設問レビュー閾値（仮置き）

- **自動差し替えは禁止**。閾値に達したら`REVIEW_CANDIDATE`のフラグを出すのみ。
- 例として同じ設問revisionの提示`n>=100`、UNKNOWN率`>=25%`、かつ全設問の同期間平均より`+10パーセントポイント`以上なら編集レビューへ（**数値は検証前の仮置きで、承認された閾値ではない**）。
- NOT_APPLICABLE率、4率、YNのUNSURE率は別の警告ルールで扱う。低頻度の設問・特定manifestの偏りは統計的に不安定なので単純な比率順位だけでは除外しない。
- 先に意味の妥当性・誤解を招く文言・選択肢の非対称性・過剰に抽象的な場面をレビュー。変更前後の設問差分・理由・承認・公開版・再計測結果を監査台帳へ記録。
- 置換時もA〜D各7問、E補助2問、意味ファミリー構成、hold-out、30問中の重複や順序制約を再検証する。

## 3. 16タイプの分布：最重要の注意点

**二つの分母を必ず併記する。**

1. `typeShareOfAllCompleted = 該当タイプに**単独暫定分類**された完了セッション数 / 全30問完了セッション数`。未確定セッションは分母に残す。
2. `typeShareAmongSingle = 該当タイプに単独暫定分類された完了セッション数 / 単独暫定分類された完了セッション数`。こちらのみ16タイプの合計が100%になる。
3. いずれも`BASE_30`と`FINAL_AFTER_YN`、`scoring_version`・`classification_version`・`questionnaire_version`を分けて集計。
4. 30問では未確定だったがY/N後に単独に絞れた件数は`ynRescueCount`とし、`ynRescueRate = ynRescueCount / 30問時点で複数候補だった完了セッション数`を参考計測。Y/Nを選択しなかった参加者と選択者の自己選択バイアスは残る。
5. 2〜16候補の結果を、1/n等で16タイプへ仮配分しない。「単独分類」「複数候補」「情報なし」のまま表示する。
6. 16タイプの出現率は**現在のルールによる分類の分布**。人口に占める割合、タイプ確率、診断精度とは呼ばない。

## 4. 結果画面パラメーター見直し（次版に向けた提案）

| 層 | 推奨表示 | 内部指標 | 注意 |
|---|---|---|---|
| タイプ概要（最初に見せる） | タイプID・名称・1行の特徴／「30問判定」「Y/N補完の暫定参考」「未確定」 | type_id、type_status、evidence_source | 「確率xx%」「診断精度」は表示しない |
| 4軸の方向 | 安定↔変化など4つの**両極ラベル**と、中央0を基準とした方向マーカー | signed_ratio −1..+1、sign | バー塗り面積を「割合」と誤認させない |
| 4軸の根拠 | 例「7段階の方向回答5/7、4は1件、判断不可1件」 | valid_count、directional_count、midpoint_count、skip_unknown_count、skip_na_count | `7`は出題数、分子は方向回答数と明示 |
| 判定の状態 | 明確／境界付近／相殺／回答不足／Y/N仮補完／未確定 | current axis statusとD255 source、itemFlipCount/familyFlipCount | 「信頼度80%」のような無根拠な数値にしない |
| 近いタイプ | 絞りきれない時のみ候補ID・差分を紹介 | candidateIds、candidate_count | 候補順位や確率を根拠なく付けない |
| 詳細情報 | 30問とY/Nで何が判断でき、何が保留かを説明 | baselineとfinalの差、Y/N回答数 | 値の名称を「参考スコア」「方向の情報量」と区別 |

**現在のグラフ**：`width = 50+50*ratio`は「左からの塗りつぶし幅」。中央が0の左右対称グラフへ変更し、未回答ならグラフの点・線を描かず「回答情報なし」とする。中間だけの場合も「どちらとも言えない」と「情報なし」を同じ灰色の確定値として扱わない。

**結果と運営指標は分離**：16タイプの**全回答者における出現率**・設問ごとの欠測率は、まず管理ダッシュボードのみ。一般受検者に「あなたは上位○%」「珍しいタイプ」などを表示するのは、データ量、選択バイアス、分類妥当性を検証してから別途判断。

## 5. DBアーキテクチャと通信境界

- 設計の候補：PostgreSQL（または同等の関係型DB）。`question_versions`／`questionnaire_versions`／`assessment_submissions`／`question_exposures`／`classification_snapshots`／`axis_snapshots`／`daily_question_counts`／`daily_type_counts`。
- **初期の収集単位は「30問完了時に、ユーザーが分析提供を明示的に認めたセッションの最終スナップショット」**。中途離脱者は収集しない。公開の静的サイトに直接DB認証情報を埋め込まない。
- 個人特定用のID、メール、IP、UA、位置情報、自由記述は分析DBに保存しない。回答はなお個人関連情報に当たり得るので、公開前に利用目的・取得項目・保持期間・削除方法・アクセス権を示し、同意・セキュリティ・法的要件を検討する。
- 送信重複には一時的なランダム`submission_id`と一意制約を使う。回答中にページを閉じても送信しない。生回答の保持期間は例として90日（仮案）とし、必要最小限に短縮・削除。集計済み匿名データは再識別リスクを評価して別管理する。
- ユーザーの合格済みVer.1〜2.1はCSP `connect-src 'none'`のまま。**収集エンドポイント、サーバー、DBの実接続、バッチ、設問差し替え、結果画面の新グラフは今回実装・デプロイしない。**
- DB側では書込み用APIと分析参照・管理者向けダッシュボードを分離。集計表から個別回答を再構築しない。低件数セル（仮にn<20）を管理画面以外では抑制する。

## 6. 受入ゲート

1. 「設問を見た回答者」分母でUNKNOWN/NOT_APPLICABLE/4を別集計。無回答をUNKNOWNへ混入させない。
2. 128マニフェスト間で非出題設問を集計分母に含めない。質問文改訂時にrevisionを分ける。
3. BASE_30とFINAL_AFTER_YNでタイプ出現率を混同しない。未確定も分母に含めた割合と単独分類者内割合を両表示できる。
4. 再送や診断結果タブ再表示で同じセッションを二重計上しない。
5. 30問の`4`、skip reason別の`null`、Y/Nの`UNSURE`は元の研究用採点と一致。
6. 受検者結果のグラフで「得点位置」「有効回答」「分類根拠」を区別し、信頼度・確率・人口比率の虚偽表示を行わない。
7. サーバー保存の実装前に、保持・同意・削除・閲覧管理と、実データによる品質検証を別途承認。
