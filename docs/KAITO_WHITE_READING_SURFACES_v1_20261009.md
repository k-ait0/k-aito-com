# KAITO 白い文字面デザイン標準 v1.0

制定日：2026-10-09  
対象：k-aito.com の公開ページ全24件（sitemapに掲載されたページ）

## 基本原則

**「外側は生成り、読む面は白、写真は写真のまま。」**

- サイト背景（`body` の `--paper`）・ブランドカラー・ロゴ・既存画像・フォント設計は維持する。
- 本文・見出し・説明文・箇条書き・注記・カード・検索結果等、情報を読む通常の面は **`#FFFFFF`** を採用。
- 枠線は薄い緑灰（`#d8e0d6`）、影は控えめ、角丸は小さくする。
- 写真の価値を損なう塗り潰しは禁止。写真内に文字を重ねる場合は**白く不透明な紙面を文字の背後へ配置**し、画像の一部が見える構成にする。
- 例外は**写真だけの領域、純粋な装飾、濃色フッター、画像主体のヒーロー背景、ステータスバッジ**。写真上に直接載る装飾的なコピー（HOMEのヒーロー）は段階的見直し対象だが、この版では従来演出を維持する。
- 通常のホバー時に本文面を生成りへ戻さない。

## 実装

正式なCSS：`white-surfaces-v1.css`（共通の最終レイヤー）

- `article-reading.css`：従来の記事専用の白紙面と文字組み。変更なし。
- `cards-v1.css`：ARTICLE／PROJECTカード分類。分類とCTAは変更なし。
- `white-surfaces-v1.css`：サイト全体で文章を読む面に白を適用。ブランド外側の生成りを保持。
- `scripts/sync-white-surfaces.cjs`：`sitemap.xml` に載る全公開HTMLの `</head>` 直前へ共通CSSを挿入し、最後のスタイルシートであることを検証。再実行で変化しない。
- `.github/workflows/sync-published-content.yml`：公開管理の同期時に上記を実行し、サイト全体のCSSの読み込み漏れを防止。
- `scripts/browser-smoke.cjs`：PC・スマホで白背景、生成りの外側、SHELVESの画像と文字、記事本文・一般画面の表示を確認。
- `scripts/live-production-check.cjs`：XServer本番にCSS実体とHTML24ページが届いているか照合。

| KIDP | プロジェクト群の説明、進捗工程、試作説明、個別Prototypeの概要・次にすること |

| LINKS | 導入文、7棚リンク一覧、案内 |

| 記事 | 既存の白い本文カードを維持。サムネイル・図・表・キャプションの可読性も統一 |
| 共通検索 | 背景白・検索結果カード白・入力部は白 |

## 品質チェック

1. `node scripts/sync-white-surfaces.cjs` で公開ページ数と変更件数を検査（2回目から原則0件）。
2. 公開ページすべてで`white-surfaces-v1.css`を**最後のCSS**として読み込む。
3. PC・スマホで各代表的な文字面が`rgb(255, 255, 255)`、外側が白以外であることを確認。
4. SHELVESの写真は表示され、文字の背面は白、文字色は濃緑であること。
5. ホームヒーローの写真・FIRST NOTE・濃色フッターを維持。
6. 水平スクロール・JSエラー・画像の破損を発生させない。
7. `main` へのコミットを公開完了とみなさず、XServerと一致するまで検証する。

## 将来の拡張

- KIDPの動的テスト画面などsitemap外の非公開／noindexページは、公開の可否を確認してから追加する。
- 個別画像のサムネイル選定・最適化は別フェーズ。
- 白地統一後も読みづらい画像内文字が残る場合は、画像編集ではなくキャプション・紙面化を先に試す。

**禁止：** 全体の `body` 背景を白に塗り替えること、ヒーロー画像やカード画像を消すこと、白面化のために記事内容を削除すること。
