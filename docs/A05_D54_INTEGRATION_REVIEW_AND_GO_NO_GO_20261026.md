# A05 D-54 — 大規模Draft PRを統合可能なレビュー単位へ固定

**2026-10-26／D54-001／PR #61：Draft・未承認・未マージ・本番未公開**

## 0. 結論

D-53時点でA05の開発版は技術面の自動テストが通過したが、心理尺度・タイプ分類の妥当性や実際の人へのインタビューは**一切承認・検証されていない**。これを「PR #61全部が完成」という意味にしてはいけない。

D-54では、PRの変更ファイルを**機能・データ保護・暫定採点・研究運用・横断QA**の5つに正確に振り分け、レビュー担当者の判断とマージ/公開の権限を切り分けた。レビュー台帳は`docs/A05_D54_PR_REVIEW_MANIFEST_20261026.json`に保持し、**すべてのファイルと区分を未承認として固定**する。

この時点の比較対象は`main`、作業ブランチは`feature/a05-d23-modular-diagnostic-20261025`。D-54着手時点で**229コミット先行・遅れ0、64ファイル差分**。台帳にはその64件と、D-54で新規作成する台帳・この文書・契約テスト3件を含む**67ファイル**を列挙する。後続の変更は追加・更新時に台帳を追記・改訂する。過去の変更記録は削除せず保全する。

## 1. 審査領域とチェック項目

ファイルごとの区分を明示することで、たとえば`questions.mjs`のレビュー完了が`storage.mjs`の保存安全性や研究開始の承認に自動伝播することを禁止する。また、`D-54`の「A〜E」は審査上のまとまりであり、**GitHubの独立したPRを既に作成したという意味ではない**。

## 2. 合理的なレビュー・統合順

1. **E: 基本の監査を固定**：台帳全件の存在・重複なし、既存の必須テストを成功させ、採点版が`-draft`かを確認。mainと差分に変化があれば再点検。
2. **B: 保存・バックアップを重点審査**：ユーザーの保存データが最も失われやすい部分。特に同意前の永続化、別タブ、失敗時の書込み停止、履歴隔離、JSONの機微情報、将来の復元による上書き防止を確認。
3. **A: UIを実機で検証**：Chrome自動検査後にiOS Safari/Android Chromeのタッチ・フォーカス・読み上げ・表示倍率・多件数履歴を確認。
4. **C: 質問と採点を別の編集/研究判断へ**：D-33の未解決BLOCK/REVISE、E軸の3候補、16タイプの解釈を確認するまで、「妥当な診断」「公式心理尺度」と言わない。
5. **D: 対人研究の実施許可は独立**：ユーザーが実際の研究責任者・保存先・保存期間を選択し、G1とD-42の承認証拠を残した場合に限り募集やインタビューの条件を審査する。

**公開の別決裁**：この順番で技術レビューが進んでも、mainへのマージ、検索エンジンへの公開、`noindex`の解除、広告連携、科学的な診断表現はすべて別の最終判断が必要。D-54はPRのDraft解除や新PRの作成、公開も行わない。

## 3. ファイル台帳の機械的契約

`scripts/test-a05-pr-review-manifest.mjs`はNode標準機能のみを使用し、追加のGitHub Actionsジョブを要しない。

- 正式のPR番号・ブランチ・base、重複しないファイル一覧、パスの存在とソート順、未審査・未マージの状態をチェック
- A〜Eの責任区分に対し、UI・保存・採点の主要モジュールが適切に分類され、研究コードが実装コード側のレビューと混ざらないことを検査
- G1の12件とD-42の16件がすべて保留であり、`studyAuthorized:false`、`productionReleaseAuthorized:false`、`automaticMerge:false`を保持することを確認
- GitHubの標準的な`refs/pull/<番号>/merge`に限り、`HEAD^1..HEAD`の**PR全体差分**と台帳のファイル一覧を完全一致で照合。追加ファイルが出た場合は台帳未登録として**CIを止める**。通常の開発ブランチでは、この完全一致テストをスキップし誤って最後の1コミットだけと比較しない。

※GitHubのPR checkout動作が変わる場合は、適切なbaseの取り方を事実確認してから変更する。失敗した契約テストを無視するためにCIを削除しない。

## 4. 実装作業でできること・できないこと

**これから独立して進められる項目**：既存のA05のパフォーマンス・アクセシビリティ検査強化、保存機構のコード・失敗時動作の改善、非復元JSONプレビュー、バックアップのデータ保護表現、QAとログの整備。

**人間の判断が必要な項目**：心理尺度としての設問採用、保存データの再インポートと破壊的上書き、正式な実研究責任、収集・保存・削除の運用体制、研究対象者への説明、G1の全承認、Draft解除・マージ・公開。

## 5. 現在の確認待ち事項

`docs/A05_D43_OPERATOR_DECISION_GATE_20261026.md`で求めた3つの意思決定——**研究の運営責任者／保存先または個別記録なし／保持期間（A/B/C）**——は未記入・未承認。研究関連のG1とD-42が保留であることを、自動で合格扱いしない。

D-54の台帳は**すべてNOT_REVIEWED**とし、「同一ブランチ上に存在する」「GitHub Actionsが通る」は担当者のレビューを経たという意味にしない。

## 7. 追加監査（D54-002）

レビュー台帳の全67ファイルについて、個人名や個別IDを含む実レビュー証拠をGitHubに置かないよう、**役割・証拠の非識別参照・日付**の3欄を追加した（現状はすべてnull）。また各領域にP0/P1のリスク優先度と、必要なレビュー役割を追記した。

- **P0**：B 保存/バックアップ、C 未検証採点、D 対人研究・承認。いずれも**人間による独立レビュー待ち**であり、PRのファイルをまとめて承認しない。
- **P1**：A UI/アクセシビリティ、E 横断テスト・運用監査。QA成功は、実iOS/Android・実スクリーンリーダーの受入完了と同義ではない。
- `reviewStatus`は現在全件`NOT_REVIEWED`。将来`REVIEWED`へ変更するなら`reviewEvidenceRef`、`reviewerRole`、`reviewedAt`の**すべてが必要**。3欄が埋まっても`mergeAuthorized:false`と公開/研究のNO-GOは別途維持する。

`scripts/test-a05-pr-review-manifest.mjs`は上記の証拠条件を検査するため**7件**となった（初期6件＋証拠/優先度1件）。また、既存の実Chromeバックアップ受入ケースに**10MiB超の合成ファイルをパース前に拒否し、既存履歴を維持する検証**を追加した。ファイル実体のサイズだけで読み込まずに停止する仕様はD-52実装済みで、今回は回帰検査の補強のみ。
