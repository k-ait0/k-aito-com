## 発見と修正

| 画面・要素 | 変更前 | D-44の変更 | 影響しないもの |
|---|---|---|---|
| 診断画面の回答進捗 | 視覚的な棒と「n問回答済み」は表示するが、進捗バー自体のARIA数値を持たない | `role=progressbar`、日本語ラベル、`aria-valuemin=0`、`aria-valuemax=30`、`aria-valuenow=現在の入力数`を追加。回答、回答変更、回答不能、取り消しの操作後に同期 | 質問・採点ロジック・回答値・端末保存 |
| 16タイプ図鑑の色グループ絞り込み | `render()`でクリックしたボタンがDOMから消えるため、キーボードフォーカスが本文に戻る可能性 | 選択された`data-filter`のボタンへ、busy解除後にフォーカス復帰。キーは既知5値だけ許可 | タイプ定義、色グループ、絞り込み結果 |
| 結果の共有文面 | 開く/閉じるとボタン自体が再生成され、フォーカスを失う可能性 | `share`ボタンにbusy解除後フォーカスを戻す | 共有テキストに生回答を含めない既存仕様 |
| 保存同意の有効化と生回答の保持切替 | 完了時にDOMが置換され操作位置を見失う可能性 | 新しい保持オプションへ移動。保持切替後も同じチェックボックスにフォーカス復帰 | 明示同意・IndexedDB保存契約 |
| 履歴の生回答削除・履歴削除・旧版削除・全削除 | 対象要素が再生成/除去されフォーカスが失われ得る | 更新後の履歴見出し等へ移動（既存の`show`によるページ移動と同じ考え方） | 削除対象・保存の成否・ロック方針 |

**設計上の注意**：A05は保存処理中の操作を禁じる `aria-busy` / `disabled` を備えるため、処理中に無理にボタンへフォーカスを当てない。busy解除後、まだ存在し有効な場合だけフォーカスする。見出しは `tabindex=-1` を付けてフォーカス対象とする。

## テスト

既存 `scripts/qa_a05_browser.cjs` にD-44 Chromiumケース1件を追加（従来16ケース→17ケース）。追加内容：

- 初期進捗が0/30、最初の回答後1/30であること
- 同じ質問の回答変更で件数が増えないこと
- `判断できない`は回答数として数え、取り消せば0に戻ること
- 図鑑で色グループG2をキーボード選択後、選択ボタンにフォーカスを保持すること
- サンプル結果の共有テキストをキーボードで開閉後、トグルのフォーカスを保持すること

確認コマンド（NodeとChromeのPlaywrightを利用できる環境）：

```sh
node scripts/qa_a05_browser.cjs
```

既存のネイティブNode契約・実ブラウザ検査を再利用し、CIワークフローやジョブは増やさない。静的HTMLの回答処理やスコア計算・質問バージョンの契約、既存IndexedDBを変更しない。
