# A05 D-50 — 保存履歴の日付を閲覧者の現地時刻で表示

**2026-10-26｜D50-001｜既存A05画面の表示のみを変更**

## 問題

従来の診断履歴では、保存された`completedAt`（UTCのISO日時文字列）の先頭10文字をそのまま日付として表示していた。しかし日本時間の `2026-10-26 00:30 JST` はUTCでは `2026-10-25 15:30Z` であり、東京の利用者に**前日の日付**で表示される。時差で月末・年末・うるう年にも影響する。

## 修正

`projects/kidp/life-design-lab/a05/format.mjs` の表示専用関数 `formatLocalCompletionDay()` に、ISO日時を閲覧している**ブラウザのタイムゾーンの年月日**へ変換する責任を切り出した。`Intl.DateTimeFormat("ja-JP").formatToParts()` で年月日の要素を取得し、`YYYY-MM-DD`を返す。日時が不正なら `日付不明` として安全に表示する。

現行 `app.mjs` の**検証済み履歴・旧版読み取り専用履歴**の2表示箇所を変更した。生データの`completedAt`、既存の日時による履歴並び替え、採点・ハッシュ、IndexedDBスキーマ、エクスポート内容は一切変更しない。保存結果の再計算・旧版の再分類も行わない。

## テスト

`scripts/test-a05-format.mjs` の独立したNodeテスト5件：

- 東京でUTC午後3時以降の完了が**翌日の日本時間の日付**になること
- 同じUTCの保存時刻を東京/UTC/ロサンゼルスで表示したとき、閲覧現地の日付が異なっても元の文字列は変わらないこと
- 2028年の閏日と年末年始の境界が正しいこと
- 不正な日時をエラー表示扱いにできること
- 明示的なタイムゾーン指定をしない通常のブラウザ表示では、その環境のタイムゾーンが使われること

既存のGitHub Actionsの条件付きA05 Nodeステップで実行し、新しいジョブ・ワークフローを作らない。

実Chromeの統合ケースでは、**Asia/Tokyoで起動した独立したQAブラウザコンテキストにのみ**架空の完了スナップショットを作成し、`2026-10-25T15:30:00.000Z` のデータが履歴画面で **2026-10-26** と表示されることを確認する。実参加者データの利用や別のブラウザの履歴操作は行わない。
