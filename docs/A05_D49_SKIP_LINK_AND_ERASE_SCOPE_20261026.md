# A05 D-49 — キーボードの本文移動と削除範囲の誤認防止

**2026-10-26｜D49-001｜Draft PR向けのアクセシビリティ/プライバシー表示改善**

## 1. 本文へ移動するスキップリンク

既存画面に`<a href="#a05-main">本文へ移動</a>`があるものの、リンク先の`<main id="a05-main">`は明示的にフォーカス可能ではなかった。キーボード操作利用者にとって、リンクによるスクロールだけでは操作位置が明確でない可能性があった。

今回、本文ランドマークに`tabindex="-1"`を付与。スキップリンクでの移動時にフォーカスできるようにし、フォーカス輪郭を表示するCSSを追加した。通常のTab移動では余計なフォーカス停止点を増やさない。

## 2. A05の「削除」が保証する範囲

既存`eraseA05DatabaseContents()`は、このブラウザのA05 IndexedDBストアを`clear()`する処理。実際のデータがOSバックアップ、クラウド同期や物理メディアに残らないことを証明する機能ではない。

従来の確認文と完了通知は「保存データをすべて削除」「消去しました」と表示していた。今回、確認の段階で**旧D-12/D-19/P0とバックアップの複製は対象外**と説明し、成功後も**ブラウザ内の新A05保存記録の削除を確認したという範囲に限定**して表示するようにした。

削除処理そのもの、IndexedDBの構造、保存データの対象範囲は変更しない。ユーザーの明示操作に先立って削除対象を正確に説明する変更である。D-41/D-42での研究記録の物理削除やバックアップ確認を完了した意味でもない。

## 3. 受入テスト

`scripts/qa_a05_browser.cjs`の既存Chrome検査に、次を追加/拡張。

- 新規1ケース：スキップリンクをキーボードEnterで使用し、`document.activeElement.id === "a05-main"`となること。
- 既存の全削除ケース：削除確認文にバックアップの限界が表示され、処理後の通知が消去の完全保証を主張しないこと。既存の再読込後に履歴・保存同意が消えている検査は維持。

D-48の44pxタッチ幅の検査と組み合わせ、旧来のブラウザ受入テストの安全性を維持する。新規のワークフロー・GitHub Actionsジョブは作成しない。

## 4. 研究と本番の境界

G1の12運用判断とD-42の16受入条件はいずれも未承認。実際の研究参加者の募集・データ収集・録音、トークン発行、本番へのマージや公開は行わない。診断の設問・採点・保存契約と既存結果は変更しない。
