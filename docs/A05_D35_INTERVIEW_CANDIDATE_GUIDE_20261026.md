## 3. 面接の提示シナリオ（研究設計案）

### 3.1 募集前条件

調査対象者への説明、任意参加・中止・記録・削除・利用目的・保存期間・閲覧権限を文書で確定し、明示同意を得る。録音と画面共有は別同意。個別回答や自由記述をGitHub/PRに登録しない。未確定の運用項目がある間は外部参加者を募集しない。

### 3.2 提示と順序

1. 面接冒頭で7段階（1〜7、4＝同程度、回答不能は別）を説明する。ただし**心理特性や「診断タイプ」を正解として示さない**。
2. 30問は基本的に `sourcePosition` 順で提示し、**各BLOCK問について案A/案Bどちらを一次提示するかを参加者群で反転**する（奇数番号はA、偶数はBという暫定割付）。残る23問は共通のD-31候補を提示する。
3. 完走を優先せず、必要に応じて途中で休止する。調査用の予備時間に、BLOCK7問の**未提示だったもう一つの案**を読んでもらい、「同じ意味か・意味が違うか」を聞く。30問すべての再回答は求めない。
4. E05案Cは、二極案とは**別の形式の調査回答**として扱う。お金と時間を別々の7段階で評価し、**差を既存のE得点に換算しない**。案Cを一次／最後のどちらで提示するかは募集前に固定・記録する。小規模面接で有意差の推定はしない。
5. 同一人物の案A/B回答は順序と再提示の影響を受ける。理解しやすさの質的比較が目的であり、A/B回答を独立標本として数えない。

### 3.3 記録・停止ルール

記録：研究上の参加者番号、調査の**どの候補**か、提示順、回答値／判断不能、想定した場面、本人の解釈（要約）、同時に重視できるか、E05の想定量。個人情報は最小化し、調査同意と分けて管理する。

一つでも多くの質問を採用することは目的でない。回答が現在の経済事情・就業・介護育児の制約から離れない場合は、その条件を隠して二極タイプ判定を継続しない。

## 5. 研究用データ契約と検証

機械可読ファイルは `schema: A05-INTERVIEW-CANDIDATES-1`、`researchVersion: A05-R-2.0.0-alpha.1`、状態 `RESEARCH_ONLY_UNAPPROVED` として区別する。

- `items` は各設問のID、源泉位置、軸、左右反転、D-33編集状態、仮の重複リンク、候補対を保持する。
- `variants[].negative/positive` は概念順、`left/right` は現行設問と同じ反転規則を適用した表示順。
- `responseFormat.E05IndependentResearchOnly` は2つの別設問（E05-M/E05-T）を定義し、**採点互換を一切主張しない**。
- `policy` の `scoringAllowed`、`productionUseAllowed`、`storedAssessmentCompatible`、`personalDataCollectionApproved`、`autosaveAllowed` はすべてfalse。これが「このまま本番に搭載しない」契約になる。
- ソース整合性のローカル検査：`node --test scripts/test-a05-research-manifest.mjs`。質問30ID・候補37件・方向・D-33状態・D-31/D-34との一致・E05の2独立項目・禁止フラグを確認する。
- **監査対象は設問構造とバージョン境界**。試験に合格しても、読みやすさや心理測定の妥当性・参加者の同意が証明されるわけではない。
- 再現用の文面と順番はGitのコミットで追跡する。実際に調査を開始する際には、同意文面とともに使用コミットSHAを明記し、その後の編集が調査中の回答に混ざらないようにする。
