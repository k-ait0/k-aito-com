# KAITO 横断検索・サムネイル整備台帳 v1.0
日付：2026-10-09　対象リポジトリ：`k-ait0/k-aito-com`

## 1. 横断検索の対象・原則

- 記事：`content-index.js` の公開記事4件。本文の一次情報は `notes/<slug>/index.html` にあり、生成された `searchText` を使う。
- プロジェクト：`sitemap.xml` に掲載された `/projects/<...>/` の**公開詳細ページ8件**。文字列の一次情報は各HTML。
- 非公開・`noindex`・`/tools/`のベータやサイトマップ外は検索対象に混ぜない。
- `scripts/sync-project-search.cjs` がプロジェクト本文・タイトル・説明文・制作状態のインデックス `project-search-index.js` を生成する。
- 公開24ページから検索インデックスを参照。HOMEの`app.js`、下層ページの`site-search.js`で記事・プロジェクト両方を表示。
- 結果は `ARTICLE` と `PROJECT` で分類。検索語をタイトル・要約・本文と照合し、タイトル一致の高いものを優先。
- 非公開を検索結果に出さない。閲覧可能な公開ページのURLのみ提示する。
- 検索用の独自外部APIを導入しない。静的配信による追加コストを抑える。

### 品質管理

`scripts/test-project-search.cjs` は8公開プロジェクトの収集、24ページへの読み込み、検索インデックスの再生成時の冪等性を検証。`scripts/browser-smoke.cjs` では`WHYNOT`でARTICLEとPROJECTを区別し、`駅生活圏`でKIDP公開詳細を見つけ、`サンケイビル`で記事に到達することをPC・スマホで確認する。

### 採用条件
1. 著作権・生成素材の使用条件を確認する。既存素材だからといって自動承認しない。
2. 記事に関係のある画像を選ぶ。無関係なストック画像を無理に採用しない。
3. WebPまたは適切に軽量化したSVG/JPEGを使用し、幅比率はカード表示の縦横に合わせて決める。
4. 画像がない記事は白背景のテキストカードを維持し、同じテーマの共通アイコンで代用できるようにする。
5. 画像の内容と本文の出典は混同しない。写真がイメージならその旨を明示。
6. HOME・ARCHIVE・SHELVESのカードで同一のサムネイルルールを共有し、個別記事の画像を毎回手作業で複製しない。

## 3. 実装記録（2026-10-09）

採用確定した2記事は、`content-index.js` の `thumbnail:{src,alt}` を一次情報とする。

- HOMEは `app.js`、ARCHIVE・SHELVES・テーマ棚は `site-content.js`、JSなしの静的一覧は `scripts/sync-published-content.cjs` が**同じ画像パス**を表示。
- 画像はCSSのトリミング（`object-fit:cover`）のみで扱い、原本のファイルを再圧縮・改変していない。
- `thumbnail-v1.css` を `scripts/sync-white-surfaces.cjs` により公開全24ページへ配信。サイト背景は生成り、文字面は白を維持。
- 元画像が存在しない・一定以上に大きい・altが欠落した場合は公開同期の段階で失敗させる。
- スマホ／PCブラウザではHOME・SHELVES・ARCHIVE・WORKSの画像読み込み、代替テキストと実際の表示寸法を確認する。
- 出典・権利の一次情報までリポジトリから追跡できているわけではないため、第三者への素材再配布の許諾は別途確認が必要。

**採用保留（2記事）**：WHYNOTは実物プロトタイプ画面を活用できる個別サムネイルを検討、サンケイビル論考は文字量の多いSVG図解の流用を避けて専用ビジュアルを用意する。無関係な素材を使って全記事に無理に画像を埋めない。
