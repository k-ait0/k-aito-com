## 改修設計の査定

**88/100点、閾値80点を通過。** 実装する範囲を以下に限定する。

1. **30問を終えたら必ず結果ページで「診断完了」**。拮抗・保留でも診断失敗とは表現しない。
2. **各軸の数値・方向・有効回答数を表示**。中間に近い理由と限界を明記。
3. **境界の仮閾値**：軸の有効回答が5問未満、または `|Σ(回答−4)| / (3n) <= 1/3` なら、単独タイプの断定に使わない。研究段階の暫定閾値であり、統計的な確信度ではない。
4. **近接するタイプの表示**：明確な軸の符号だけを固定し、曖昧な軸は両方向の候補を残す。候補1つなら暫定タイプ、2〜4個なら全候補を併記、8〜16個なら候補数と4軸の解釈を表示し、適当な4件を優先表示しない。
5. **追加質問は希望者のみ**：判定に使いにくい軸へ未出題の設問2問を追加。最大2回（合計34問まで）。既存回答を保持し、同一軸内の各設問の重みは等しく1.0。D208のC31/C32の条件比較ペアは分離しない。
6. **追加後も拮抗するなら保留を維持**。結果を無理に確定させる目的で質問数を際限なく増やさない。
7. **プライバシー・本番分離**：回答はページ内のみ、送信・保存なし。本番A05v1、D206銀行、D208サンプラー、認証、研究用フォームを変更しない。GitHub Pagesは研究ブランチから生成した単独HTMLのみ。
