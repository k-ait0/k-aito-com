# A05 D-120｜共通30問＋個別適応型追加質問（Y/N併用）設計仕様

**2026-11-09／研究・設計候補。未承認・実装未着手。本番・v2質問BANK・採点・履歴・PDFを変更しない。**

## 意思決定と目的
- 全員共通の30問（5軸×6問、7段階＋判断不能）を入口とし、**A〜Dのうち判定が不確かな軸だけ**追加問題を選択する。Eは補助軸であり16タイプ確定の条件に混ぜない。
- 追加質問は個人により**数・順番・出題文が異なってよい**。各軸の既存30問の回答内容、欠測、方向の弱さ、文脈上の回答不一致を参考に分岐を決める。
- 追加質問は「7段階の追加」だけでなく**状況限定のY/N**と**両端を明示するA/B二択**を混在させてよい。すべて任意回答として「判断できない／該当しない／回答しない」を選択可能にする。
- **分類できないことも有意な出力**。意図せずタイプを確定させるために質問を続けない。
- 既存16タイプは編集的インデックス候補であって、自然な性格類型の実証ではない。B/C軸の構成概念・二極採用は依然未決定。

## 出題と停止のプロトタイプ（正式な統計的CATではない）

1. 簡易30問を現行の有効回答・中立・欠測区別を維持して採点。欠測は0点とみなさず、回答4は有効回答として扱う。
2. 追加を案内する軸を抽出：方向未判定（例：sum=0、回答4問未満）を第一候補、方向が出ても微小差/暫定の軸を次の候補とする。採否に用いる境界は**実データで校正するまで正式決定しない**。単なる6問の相殺/分散だけで「葛藤」や「無関心」を推論しない。
3. 判定不確かな軸が複数あれば、最大未解決度の軸から開始する。新しい文脈（住環境→生活ルール、自己判断→関係者への配慮、現在の経験→将来便益、関心の幅→活動深度）を優先し、同じ設問の言い換えを回避。
4. **最初に1〜2問を試し**、回答に応じて次の問いを選ぶ。順方向の支持質問だけを追加せず、反対方向にも支持・反証できる対照ケースを混ぜる。必要量はパイロットまで未確定。
5. 停止条件： (a)選択した研究上の閾値/一致度を十分満たした、(b)設問上限を超えた、(c)本人が終了した、(d)相反/適用不能が続き、追加で分類を強制すべきでない、のいずれか。**終了＝単一タイプ発行ではない。**
6. 結果は「軸別表示」「タイプ名の候補」「分類保留」を分離する。1軸だけ境界のとき2候補表示は**UI比較案**、2軸なら4候補となり得るため自動的な4候補表示を前提としない。

## 質問形式の扱い

| 形式 | 例 | 解釈・注意 |
|---|---|---|
| Y/N（極性確認） | 「双方に重大な不利益がないとしても、自分の希望を優先して決めますか？」 | **Yes**はその場面の「自己希望優先」を支持する。**No**は必ずしも「他者優先」を示さず、判断留保・別条件などの可能性がある。 |
| 反対極性のY/N | 「同じように重大な不利益がない場面で、関係者の希望を優先して決めますか？」 | どちらもYesでも誤回答と断定しない。状況によって変わるかを確認。肯定しやすさのバイアスを検査する。 |
| 明示的なA/B二択 | 「十分な休養と生活費が確保され、同程度の負担なら、追加の時間は（A）将来の準備（B）現在だけの経験のどちらに使いたい？」 | 二極の限界優先を直接問う。ただし便益量・費用・確実性の非等価と文脈依存は残る。「選べない／どちらも該当しない」を許す。 |
| 7段階 | 既存の回答に近い、比較的穏やかな新しい場面 | 追加回答を元30問へ単純な等重み合算はしない。形式別の校正・等化が必要。 |

**Y/Nの「No」を逆側の得点として即加算しない。** 独立Y/Nを2つ出すことでB2/C2の両高/両低を表せても、それはB1/C1の二極スコアとは別の測定対象であり、数値自動変換は禁止する。

## 軸別の例示・分岐（いずれも採用前の試作文言）

### A：生活基盤の継続・更新（D：分野の探索・深耕から切り離す）
- A-FU01（Y/N）：現在の生活環境に大きな不満がなく、移行の負担と安全性が同程度でも、今後数年のうちに生活拠点を変えたいと思いますか？
- A-FU02（A/B）：仕事や興味の対象は変えず、生活基盤そのものについて、A：既存の基盤を育て続ける／B：新しい基盤を築く、どちらを選びたいですか？
- 旧A02/D03の店舗新規開拓の繰り返しを避ける。A-FU01がNoでも自動で安定側確定とはしない。

### B：関係する人との意思決定（B1相対方式の研究例）
- B-FU01（Y/N）：自分と関係者の希望がぶつかり、双方に重大な不利益がなく話し合いも済んだ場合、最後は自分の希望を優先して決めますか？
- B-FU02（対向Y/N）：別の場面で同条件なら、最終的に関係者の希望を優先して決めますか？
- B-FU03（A/B）：同じ内容の意思決定で、A：自分の納得を優先／B：関係者との一致を優先、どちらに重きを置きたいですか？
- B-FU01/02が両方Yesの場合、迎合癖か二極性の不成立か、あるいは場面・関係性の違いかはこの情報だけでは判定できない。

### C：将来と現在の時間配分（C1相対方式の研究例）
- C-FU01（A/B）：基本的な休息と義務を確保した上で追加の自由時間が生まれたとき、A：将来の選択肢を増やす準備／B：今だけの経験、どちらに配分したいですか？
- C-FU02（Y/N）：同程度の負担で将来の成果が必ずしも得られなくても、今の満足よりも将来への準備を選びますか？
- C-FU02は将来成果の不確実性の影響を強く受けるため、将来志向の純粋指標として扱わず**交絡検査専用**。便益の確実性が違う条件を比較して反応が変わるか確認する。

### D：関心・学習対象の幅と深さ（A：生活基盤の変更と切り離す）
- D-FU01（Y/N）：現在の生活・職場を変えず、使える学習時間が同じでも、今の専門を深める代わりに新分野を学びたいですか？
- D-FU02（A/B）：同じ学習機会があれば、A：一つの領域を深く掘る／B：複数の領域を広く試す、どちらを選びますか？
- D軸の方向は現行コードでは**左=探索(-)、右=深耕(+)**。追加問題のA/BやYes/Noのラベルをそのまま既存符号として扱わない。

## 実装境界：後の開発時に守る契約

- 今の30問・v2 engine.mjsの採点契約、保存済みv1 snapshot、旧結果の読み取り専用とバージョン識別はそのまま。
- 別モジュールの研究用アダプティブルータを構想。入力は**既存の軸結果と回答理由を特定せず確認できる状態**、出力は `nextItemId` / `axis` / `reason` / `researchStatus` / `remainingLimit` / `optional`。入力値は欠測区分を含む。新規個人回答を保存・送信しない。
- 追加質問BANKは軸、構成概念、題材、文脈、Y/N肯定方向、反対方向の対照、制約条件、適用可能性、版、元30問との重複候補をメタデータに持つ。
- 本番30問とは異なる形式を混在させるため、**Y/N回答を7段階回答と無校正で合算しない**。統計的CAT/IRTの意味で「最も情報量の多い質問」を選ぶには項目反応データと校正済みBANKが必要。先行段階は「ルールベースの個別分岐型」と明記。
- 出題数の目安は初期の試験計画であり、採用前に認知面接・パイロットで負担と情報増分を検証する。不要な長期保存、解析トラッキング、他サイト連携を行わない。

## 検証・公開ゲート

1. 30問終了後の判定不能・微差・未回答・複数軸未確定・矛盾パターンから、**該当軸以外の問題を出さない**ルーティングの単体テスト。
2. 左右の極性・Yesの支持対象・Noが逆極性を確証しないこと・「判断できない」を保持する契約テスト。
3. 同じ入力なら同じ問題（固定BANK版／決定的ルータ）、質問重複なし、該当分野の過度な反復なし、各参加者の終了時に分類保留可能、旧レコード不変更。
4. 人を対象とした認知面接でY/Nの読み違い・肯定バイアス・場面差・負担を調査。統計的アイテム選択は回答データ校正後にのみ検討。
5. B/Cの構成概念・旧16タイプの扱い、G1/D-42と個人情報・結果表示、ネイティブ/ブラウザQAおよび人間の公開承認までは**本番NO-GO**。
