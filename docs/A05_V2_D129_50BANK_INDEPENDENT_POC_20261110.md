## 実際に実装した仕様

| 要素 | D-129の技術仕様 | 留保 |
|---|---|---|
| 抽出件数 | A/B/C/D各12候補から7、Eの2候補は両方、合計30 | **50件のレコード**は実在するが採用可能な独立項目が50問完成したわけではない |
| seed再現性 | 同じバンク版＋同じseedならID/順序/問題文が一致。別seedで異なる出題組 | 比較可能な心理得点は未保証 |
| 重複回避 | 確認済みのA02とD03を同時抽出しない `VENUES_NOVELTY` グループ | その他のA05/D04等の重複は未解決。すべての意味重複を機械判定したわけではない |
| 途中保存 | 当該セッションの出題ID・問題文・順番・版・回答を一体でJSON化、復元時にseedとバンクから再構築・照合 | FNV-1a 32bitは**非暗号学的デモチェックサム**。本番ではSHA-256等に変更が必要 |
| 不明回答 | 有効7段階=1〜7と `null`（判断不能）を区別。未回答はキー未登録 | 回答率・欠測の心理解釈はしない |
| 境界トリガー | A〜D、有効回答数`n<4`で回答不足、`n>=4`なら`abs(sum)*10 <= 3*n`が45〜55% | D-122に基づく**仮の数理ルール**。実利用者の不確実性やSEMの推定ではない |
| E補助 | 有効数2未満は不足、2問で均衡なら任意追加を案内する参考状態 | Eの分類なし／既存エンジンのE判断を流用しない |
| 16タイプ | 生成禁止、常時`WITHHELD` | 構成概念と採点が未校正 |
| 回答後の自動追加 | 追加質問ルーティングは**フラグ出力のみ** | D-125の詳細質問への本物の振分け／得点統合は未実装 |
| 多軸加点 | 明示的に禁止 | このPoCでの複雑度を固定するため |

## 検証結果と証拠の範囲

- **V8 JavaScript上で関数を実行し15/15の検査に合格**：50件バンク形、7/7/7/7/2件数、seed同一性、manifest検証、異なるseedの多様性、250seedでA02/D03非共起、原本順を逆転しても同一抽出、保存・復元、`null`と中立の区別、全問中立時の境界判定、Eの2問、productionフラグ拒否、未知ID拒否、件数不足拒否、改変manifest拒否。
- **追加で1,000個の模擬seedを試行**：未作成枠が出現した数は平均4.734問、最少1問、最多8問。分布は1件:7回／2件:47回／3件:118回／4件:229回／5件:319回／6件:202回／7件:68回／8件:10回。この分布は仮のseed・抽出器・バンクだけによるものであり、心理特性の実証には無関係。
- **Node向け15テストファイルは追加したが、native Node実行未検証**。オフラインHTMLについてはJS構文解析と基本的なDOM要素の静的確認のみ。Chromium/Playwright、iOS Safari、画面リーダーでの操作検証は**未実施**。
- 既存保存仕様（IndexedDB）、v1の結果履歴、公開中のA05への読み書きは**一切していない**。

## 技術実現性の評価

**研究PoCの出題・seed再現・質問ID保存・基礎ルータは成立。既存v2への軽微なパッチでは実装できないというD-128の結論は変わらない。**

現行の固定30 IDと6問・各軸構造（`questions.mjs`・`engine.mjs`）、固定順を前提にする`app.mjs`、質問ハッシュと版を結び付ける`storage.mjs`、E有効4問以上を前提にする`report.mjs`は、別版の可変出題・保存契約で扱う必要がある。

今回のPoCはこれらを**直接書き換えずに隔離**できたが、製品へ導入するなら質問バンク、採点器、スナップショット版、UI、履歴読み取り、回帰テストがまたがる中〜大規模作業になる。
