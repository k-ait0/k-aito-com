# A05 D-56 — 別タブの下書き上書きを防ぐ二重照合

**日付：2026-10-26｜D56-001｜Draft PR #61の未公開試作への修正**

## 検出した障害モード

既存の`replaceDraft(db,nextDraft,hash,expectedRevision)`は、「新しい診断を始める」際に下書きの`revision`だけを比較して`active`レコードを置換していた。現在の下書きAの`revision=0`と、別タブで確定・新規開始した下書きBの`revision=0`は**違う診断であるにもかかわらず同一番号**となる。その際、古いタブの「新しい診断を開始」でBの途中回答を気づかず失う可能性があった。

`saveDraft`と`finalizeDraft`はIDと更新番号の双方を照合していたが、`replaceDraft`のみ片方が欠けていた。

## 修正内容

- `storage.mjs`の`replaceDraft`へ`expectedAssessmentId`を追加。原子的なIndexedDB`readwrite`トランザクション内で`actual===expectedRevision`かつ**保存済み下書きが存在する場合はその`assessmentId`も一致**しなければ`REVISION_CONFLICT`として中断する。
- `app.mjs`から既存`state.draft.assessmentId`を引数に渡す。新しい診断を開始するUIと同意・採点の既存契約は維持する。
- 下書きが存在しない場合、予期した更新番号が`null`のときだけ新しい下書きを作成できる。確定済み履歴は書き換えない。
- 競合で`REVISION_CONFLICT`を受けると、既存の画面側が警告し、通常保存を停止する。再読み込みで最新状態を照合するまで古いタブから書き込まない。

## テスト

`scripts/test-a05-storage.mjs`に3件追加：

1. Aが`revision=0`で確定→Bが`revision=0`で保存→Aの古いタブが同じrevisionで新規開始を要求してもID不一致で拒否し、Bの下書き、確定済みA、保存同意が残る。
2. 正常な診断の切替えでは正しいID/更新番号のセットで進み、ID/更新番号が誤る場合は保護する。
3. 現在の下書きが存在せず、期待`revision=null`なら新規作成できる。古い更新番号の場合は拒否する。

`scripts/qa_a05_browser.cjs`に実Chromeの**独立ブラウザコンテキスト／2タブ**の回帰1件を追加。別タブが診断IDを変えて同じ更新番号0で保存した後、古いタブの「新しい診断」を実行しても保存処理が拒否され、更新後のIDと更新番号が残り、UI側が警告・停止することを検証する。作成するIDは合成QA用で、実利用者データを扱わない。
