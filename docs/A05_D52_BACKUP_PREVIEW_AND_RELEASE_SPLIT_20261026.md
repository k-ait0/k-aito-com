# A05 D-52 — バックアップの安全な事前確認とDraft PRの分離レビュー

**作成：2026-10-26｜版 D52-001｜PR #61 未統合・本番未公開**

## 1. 実装レビューで追加した機能

D-51でバックアップを5ストア同一トランザクションへ修正したが、出力後のJSONファイルをA05アプリに対して**構造検査する機能はなかった**。復元や上書き機能をいきなり実装すると、既存の確定履歴や復旧待ちの隔離データを壊す可能性がある。まず、**ユーザーが明示選択したローカルJSONの読み取り専用検査**だけを追加した。

実装対象：
- `projects/kidp/life-design-lab/a05/backup-inspect.mjs`：副作用のない`inspectA05Backup()`。A05-EXPORT-1版、書き出し日時、5保存領域の配列・非空識別子・領域内の重複を確認。返却するのは**ストア名と件数、合否、失敗理由のみ**。元の回答・ID・個人情報を返却しない。
- `app.mjs`：診断履歴画面の手動ファイル選択。最大10MiB、`File.text()`で読み込み、表示するのは5領域の**件数だけ**。検査が不合格でも、現行の端末保存・履歴・同意の状態は変更しない。`JSON.parse`で取得した実内容を`state`に保持せず、DOMへ表示しない。
- `style.css`：ファイル入力を320px幅の画面でも横にはみ出さない表示。
- `scripts/test-a05-backup-inspect.mjs`：5件のNode契約テスト。正常形式、異なる版、不正日時、保存領域の不足/追加、重複IDや壊れたレコード、回答内容を返却しないこと。
- `scripts/qa_a05_browser.cjs`：Chrome統合テスト1件。架空のJSONは件数だけ表示、形式不正や壊れたJSONでも既存の履歴が変わらず、再読み込み後にプレビューは残らない。

**重要な機能境界**：これはデータの暗号学的完全性検証でも、バックアップの復元・インポートでもない。構造が正しいように見えるJSONの中身が真実か、他人の記録か、現在の採点・質問版と整合するかを保証しない。**任意の未承認データをアプリへ上書きする機能はない。** ブラウザ外への送信、解析API、GitHubへのアップロードも実施しない。
