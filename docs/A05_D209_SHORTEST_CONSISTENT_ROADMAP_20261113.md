**目的：50問の編集バンク→根拠のある30問診断へ。** 既存の「候補追加→仮分類→大量抽出テスト→保留」という循環を終了する。

- 編集版：D206 v1.2の50問（A/B/C/D各12、E2）。旧D202以降の変更履歴は保持。
- 技術：D208非本番抽出器。GitHub Actions Run 43346728216で追加14/14・既存146/146、抽出200,000件／checkpoint50,000件、既存D170/D175ブラウザ回帰が成功。

- 16タイプは4軸の方向の組合せ。神話モチーフ等の別分類ロジックとは混同しない。

## 3. B/Cの矛盾を回避する暫定設計（最終決定ではない）

B「自律かつ関係参加」、C「将来準備かつ現在充実」は、**二つとも高く／二つとも低くなり得る**。

50問の既存形式は「二つのうち、相対的にどちらを優先するか」という**相対選好**としてのみ試行し、個々の価値の絶対的な強度・人格・社会性は推定しない。中間値を「両方高い」「両方低い」のどちらとも断定しない。研究フォームで別途**非採点の独立7段階評定**を用意し、相対選好と両立度の関係を見る。結果次第でB/Cの尺度を再設計し、その際は回答形式・バンク・採点バージョンを一緒に改訂する。形式の違う問を黙って一つの得点に足さない。

E2問は「豊かさの絶対評価」ではなく、提示金額／自由時間の交換比に依存する**補助的な選択**。そのまま安定した人物特性として採点しない。

## 4. 次の開発に直結する最小仕様

**一つの研究フォームに2モードを持たせる。** 同じ設問部品を使い、全50問回答は将来のフォーム間比較に用いる。30問モードはD208抽出manifestで表示しUIの操作性を確かめる（独立したアプリを作らない）。

研究データに必要な項目は、設問バンクのdigest、manifestと選択位置、設問ID、回答1〜7またはnull、回答形式バージョン、回答者の同意状態、自由記述の解釈メモ、実行モード。**氏名・連絡先・住所・IPをデータ仕様に含めない。** 初期は端末内で保持し、明示操作のJSONエクスポートのみ。公開サーバーへの自動送信なし。

30問フォームと50問フォームの回答を無検証で混在させず、同じ構成概念の測定結果と断定しない。

## 6. 工程の停止条件（ループ防止）

- 技術試験に変更がない限り、抽出ケース数を増やして「進捗」としない。
- 新たな設問案を加える場合は、削除する既存IDと差し替え理由がない限り候補バンクに加えない。
- 大量の仮想回答は**プログラムの異常検出**に使えるが、構成概念の妥当性・信頼性の実証に用いない。
- 採点ロジックの本番変更・既存A05スナップショットの再計算・モチーフと16タイプの混同を禁止。
- 単に「設問50件／テスト全通過」をもって公開準備完了と報告しない。

## 7. 現時点の作業順序

**直ちに：G1の比較監査とG2の回答UIを並行開始 → 実人間の解釈確認 → 同一人の全50問から抽出差の検証 → 専用v3採点・画面連携 → 公開判定。**

承認が必要なものは「尺度そのものの変更」「診断結果の本番公開」「実回答の保存・共有ポリシー」。研究フォームの非公開プロトタイプと静的QAは止めずに進める。
