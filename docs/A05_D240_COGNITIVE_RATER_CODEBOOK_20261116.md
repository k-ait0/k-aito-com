# A05 D240｜認知面接・独立評価者の判定コードブック

**対象**：D237空欄面接キット、D238評価者コード、D239空欄パッケージ。  
**研究用途のみ／UI評価から除外／実回答0件**。ここに記した判断は、実際の回答者による認知面接の結果ではない。

## 1. 面接の基本手順

- 面接開始前に研究目的、任意参加・中止可能性、記録する内容、使用範囲、保存期間、撤回方法を説明し、同意が得られなければ実施しない。
- D237の各設問の文面を**1問ずつ**提示する。まず各質問の意味を参加者自身に説明してもらい、回答番号（1〜7／スキップ）と判断理由を聞く。設問同士の類似性はこの段階では示唆しない。
- 2問に回答した後で初めて、同じ理由・別の理由・答えにくい条件を尋ねる。誘導的な「重複していますね」は使用しない。
- 重要度P0のC31–32・C35–36・E49–50を全枠で確認する。非P0の15組は24枠で各8回となるよう割り当てる。
- C36-R1/R2は順序を半数ずつ入れ替える。R3は**時間割引や先送りという別概念を確認する負の対照**であり、採点候補ではない。
- D210のB/C独立プローブ（B_AUTONOMY、B_CONNECTION、C_FUTURE、C_PRESENT）はそれぞれ1〜7で答え、16タイプ採点には入れない。特に「4」の理由を言葉で確認する。
- 面接後の原文回答、言い換え、判断理由は匿名でローカルに保管する。氏名・連絡先・住所・職場等の直接識別子を記録せず、生の記録を公開リポジトリやCI artifactへ送信しない。

## 2. 2人の評価者が独立に付けるコード

評価者R1/R2は**他方のコードを見ずに**判断する。両者は同じ匿名の設問回答・言い換え・判断理由を参照するが、初回のコードが確定するまでは相談しない。

| D238の `pairJudgments[...].code` | 操作的な意味 | 判定例・留意点 |
|---|---|---|
| `SAME_REASON` | 参加者が2問をほぼ同一の価値判断で回答している | 事例の名詞だけ異なり、本人が重要と述べる根拠は同じ |
| `DISTINCT_REASON` | 選んだ理由に別の認知的判断基準があり、その差を本人が説明できる | たまたま1問目が1、2問目が7でも、理由が違うという証拠にはならない |
| `CONFOUNDED` | 質問が本来の軸以外の条件に強く左右され、独立性の評価が難しい | 希少性、対人アクセス、価格、時間割引、技能、リスク選好 |
| `UNCLEAR` | 意味の説明が不足していて、同一・別概念・交絡のいずれとも判断できない | 低い確信度で推測して補わない |
| `SKIPPED` | 質問が未回答、面接中断、または同意撤回により比較不能 | 「重複なし」と数えない |

`criticalMisunderstanding`：少なくとも一方の質問文を、想定した価値観と**実質的に異なる意味**で理解したと評価者が認める場合は `true`。単に迷った・選びにくかっただけなら自動的に `true` にしない。何を誤解したかは非公開の原資料に残す。

## 3. C36差し替え候補のコード

| `candidateJudgments` | 判定 |
|---|---|
| `NEW_C_FACET` | C軸の将来／現在に関する**既存C25/C26/C35にはない**判断理由を参加者が説明したと評価できる |
| `OVERLAPS_EXISTING` | 既存C25/C26/C35等と実質同じ理由に収束 |
| `OTHER_CONFOUND` | 時間割引、保存志向（A軸）、不確実性等の別概念が主因 |
| `UNCLEAR` | 判断理由が不明確 |
| `SKIPPED` | 有効回答がない |

R1/R2による `NEW_C_FACET` の一致は、**正式採点に採用する根拠ではない**。C36-R1/R2を次の定量パイロットに進めるか、内容の再編集を要するかの候補にすぎない。C36-R3については負の対照として扱うため、いかなるコードが付いてもC軸採点に追加しない。

## 4. 集計の読み方（D238）

D238では以下を明確に分けて報告する。

- `pairedReviews`：2評価者の両方が提出したペア数。未回答を含む。
- `agreements`：2人のコードが同一だった総件数。両方 `UNCLEAR` や `SKIPPED` でも増えるため、**実質的な一致率に使用しない**。
- `substantivePairedReviews`：2人ともSAME_REASON／DISTINCT_REASON／CONFOUNDEDのいずれかを付けた件数（C36候補はそれぞれ対応する実質3コード）。
- `substantiveAgreements`：その実質コード同士が同じだった件数。
- `substantiveAgreementRate`：`substantiveAgreements / substantivePairedReviews`。分母が0なら数値を作らず `null`。
- `criticalMisunderstandingEither`：一方でも重大な誤解ありと報告したペア数。**不一致であっても内容レビューの優先対象**。

参加人数が少ないペアの一致率を一般化しない。必要なら分母、判断不能・スキップ率、各評価者の独立判断を併記して、内容の監査につなげる。生の回答は集計器に渡さない。

## 5. 不一致時の処理

1. 一致率だけで設問の採用・棄却を自動決定しない。
2. 評価者R1/R2がいったん独立コードを提出し、差の出たペアについて原資料を再確認する。
3. 双方の解釈の違いと、その根拠となった具体的な回答理由を**非公開の合議記録**に残す。
4. 合議でも保留なら `HOLD_MORE_EVIDENCE` とし、新たな実回答・再面接で確認する。
5. 重大な誤解が見つかった設問は、修正文面を比較検証するまで正式採点へ移行させない。
6. どの設問にも「本番採点承認」を自動的に付与しない。

## 6. 合格ゲート

- **D237〜D239のテスト合格**は面接準備とデータ処理の技術的合格。
- **G1/G3の実証上の合格**は、実際の面接・言い換え・判断理由・独立レビューに基づく編集決定が必要。
- **G4の合格**は、さらに同意を得た全50問データで、p=1.5、判定境界、追加質問による変動を比較する必要がある。
- G1/G3/G4/G5は、実回答がない現段階では引き続き `BLOCKED` / `AWAITING_DATA`。

**リポジトリで管理するのはコード、空欄キット、匿名集計仕様、研究計画だけです。**
